# AOP

Introduce mecanismos transversales de Spring y alternativas arquitectónicas sin perder el modelo mental.

## Qué vas a conseguir

Al terminar esta lección podrás:

- Explicar **AOP** y reconocer cuándo se aplica.
- Interpretar el ejemplo guiado y señalar el resultado esperado.
- Realizar una modificación controlada y comprobarla con una ejecución o prueba.

## Punto de partida

**Bloque:** Capacidades avanzadas de Spring.

Antes de empezar, revisa el ejemplo de esta lección e identifica qué parte corresponde a la aplicación y qué parte proporciona el framework o la herramienta utilizada.

## Ejemplo guiado

```java
@Transactional
public void operation() { ... }
```

Analiza la transacción como preocupación transversal que Spring aplica mediante infraestructura AOP.



## Relación con el resto de la ruta

AOP, proxies, eventos y cache explican parte del comportamiento transversal de Spring; MVC/WebFlux son modelos web distintos.



## Ejemplo adicional: aplicación práctica

```java
@Aspect
@Component
class MedicionTiempo {
    @Around("execution(* es.ejemplo.service..*(..))")
    Object medir(ProceedingJoinPoint punto) throws Throwable {
        long inicio = System.nanoTime();
        try { return punto.proceed(); }
        finally { /* registrar duración */ }
    }
}
```

AOP encapsula comportamientos transversales, no reglas de negocio.

**Comprueba:** identifica qué clase, anotación o propiedad se encarga del comportamiento descrito y realiza una modificación pequeña para observar su efecto.

## Ejercicios propuestos

1. Construye un ejemplo pequeño y aislado de **AOP**.
2. Compara su comportamiento con y sin la característica y explica en qué momento interviene Spring.
3. Crea una prueba que verifique el resultado observable y no solo la presencia de una anotación.

**Evidencia de aprendizaje:** entrega el código o configuración modificada, una prueba o comando de verificación y una breve explicación del resultado.

## Qué debes recordar

- **AOP** tiene una responsabilidad concreta en el diseño o ejecución de la aplicación.
- Comprueba el resultado mediante una prueba, un comando o una petición según el contenido trabajado.
- Distingue entre código de negocio, configuración y servicios aportados por Spring.
