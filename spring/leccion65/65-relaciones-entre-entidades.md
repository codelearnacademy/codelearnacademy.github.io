# Relaciones entre entidades

Relaciona tareas y categorías con JPA y verifica la clave foránea en PostgreSQL.

## Qué vas a conseguir

Al terminar esta lección podrás:

- Mapear una clave foránea con `@ManyToOne` y `@JoinColumn`.
- Identificar el lado propietario y el atributo indicado por `mappedBy`.
- Comprobar la relación desde Swagger UI y PostgreSQL.

## Punto de partida

**Bloque:** Persistencia con JPA y PostgreSQL.

Antes de empezar, revisa el ejemplo de esta lección e identifica qué parte corresponde a la aplicación y qué parte proporciona el framework o la herramienta utilizada.

## Ejemplo guiado

Una categoría puede agrupar varias tareas. Cada tarea tiene una categoría. En Java, `TaskEntity` mantiene una referencia a `CategoriaEntity`. En PostgreSQL, `tareas.categoria_id` guarda el identificador de esa categoría.

| Tabla | ID | Dato | Clave foránea |
|---|---:|---|---|
| `categorias` | 3 | FP | |
| `tareas` | 1 | Preparar entrega | 3 |
| `tareas` | 2 | Revisar práctica | 3 |

### Mapear la relación en JPA

Este fragmento amplía la entidad de tareas de las lecciones anteriores. `CategoriaEntity` representa la tabla `categorias` y tiene un atributo `id` anotado con `@Id`.

```java
import jakarta.persistence.*;

@Entity
@Table(name = "tareas")
public class TaskEntity {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    private String titulo;

    @ManyToOne(fetch = FetchType.LAZY, optional = false)
    @JoinColumn(name = "categoria_id", nullable = false)
    private CategoriaEntity categoria;

    protected TaskEntity() {
    }
}
```

- `@ManyToOne` se coloca en `TaskEntity`, el lado «muchos». Varias tareas pueden referirse a la misma categoría.
- `@JoinColumn` indica que la clave foránea está en `tareas.categoria_id`. Por defecto, referencia la clave primaria de la categoría.
- `optional = false` expresa la obligatoriedad en JPA. La migración Flyway debe establecer `NOT NULL` y la clave foránea en PostgreSQL.

Si necesitas navegar desde la categoría hacia sus tareas, añade este atributo a `CategoriaEntity`:

```java
@OneToMany(mappedBy = "categoria")
private List<TaskEntity> tareas = new ArrayList<>();
```

`mappedBy = "categoria"` señala el atributo Java de `TaskEntity` que gestiona el vínculo. Ambas referencias representan la misma clave foránea. Para esta práctica basta con `@ManyToOne`.

### Preparar la base de datos

Añade una migración Flyway como la siguiente si `tareas` existe y `categorias` y `categoria_id` aún no se han creado. Si ya tienes la tabla de categorías, adapta la migración para reutilizarla y asigna cada tarea existente antes de activar la obligatoriedad.

```sql
CREATE TABLE categorias (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    nombre VARCHAR(120) NOT NULL
);

INSERT INTO categorias (nombre) VALUES ('FP');

ALTER TABLE tareas ADD COLUMN categoria_id BIGINT;
UPDATE tareas SET categoria_id = (SELECT id FROM categorias WHERE nombre = 'FP');
ALTER TABLE tareas ALTER COLUMN categoria_id SET NOT NULL;
ALTER TABLE tareas ADD CONSTRAINT fk_tareas_categoria
    FOREIGN KEY (categoria_id) REFERENCES categorias(id);
```

### Propuesta de relaciones para la API de tareas

| Regla de negocio | Mapeo JPA | Restricción en PostgreSQL |
|---|---|---|
| Toda tarea tiene una categoría y una categoría puede agrupar muchas tareas. | `TaskEntity.categoria` con `@ManyToOne`. Añade `CategoriaEntity.tareas` con `@OneToMany(mappedBy = "categoria")` si vas a navegar en ese sentido. | `tareas.categoria_id NOT NULL` referencia `categorias.id`. |
| Una tarea admite varias etiquetas y una etiqueta puede aplicarse a varias tareas. | `@ManyToMany` con `@JoinTable` en la entidad propietaria. Si necesitas navegar al revés, usa `mappedBy` en el lado inverso. | `tarea_etiqueta(tarea_id, etiqueta_id)` tiene dos claves foráneas y clave primaria compuesta. |
| Una tarea puede tener una ficha de detalle y cada ficha pertenece a una tarea. | `@OneToOne` y `@JoinColumn` en `TareaDetalleEntity`. | `tarea_detalle.tarea_id` es una clave foránea `NOT NULL UNIQUE`. La ausencia de una fila de detalle representa una tarea sin ficha. |

Si la asignación de una etiqueta guarda datos propios, como `fechaAsignacion` o quién la añadió, usa una entidad `TareaEtiqueta` con dos relaciones `@ManyToOne`. Conserva una restricción única sobre el par de identificadores.

**Orden de práctica.** Primero crea dos tareas con la misma categoría y comprueba la clave foránea con un `JOIN`. Después añade dos etiquetas a una tarea y comparte una de ellas con otra tarea. Comprueba las filas de la tabla intermedia. Como ampliación, intenta añadir una segunda ficha a la misma tarea y comprueba que se rechaza.

Usa identificadores en los DTO y mapea las entidades a respuestas de la API. Así puedes representar la categoría y las etiquetas sin serializar todo el grafo de entidades. Consulta [SportRent en la ruta de ORM]({{ '/orm/leccion30/' | relative_url }}) para comparar el mapeo de claves foráneas.

## Ejercicios propuestos

1. Amplía el ejemplo para que el DTO de creación reciba `categoriaId`. En el servicio, busca la categoría en su repositorio, asigna la entidad encontrada y guarda la tarea. Si la categoría no existe, devuelve `404` sin insertar una fila.
2. En PostgreSQL, consulta el ID de la categoría «FP». En Swagger UI, ejecuta `POST /api/tareas` con `{"titulo":"Preparar entrega","categoriaId":1}`, sustituyendo `1` por el ID obtenido. Comprueba el `201` y copia el ID de la tarea.
3. Verifica el vínculo en PostgreSQL. Sustituye `1` por el ID de la tarea devuelto por la API:

```sql
SELECT t.id, t.titulo, t.categoria_id, c.nombre AS categoria
FROM tareas t
JOIN categorias c ON c.id = t.categoria_id
WHERE t.id = 1;
```

**Evidencia de aprendizaje:** entrega el JSON enviado, el código HTTP y la fila devuelta por la consulta. Añade una prueba con una categoría inexistente y comprueba que la tarea no se guardó.

## Qué debes recordar

- La clave foránea vive en el lado «muchos», `tareas`.
- `@ManyToOne` y `@JoinColumn` vinculan la referencia Java con esa clave.
- El DTO recibe un identificador y el servicio resuelve la categoría antes de persistir la tarea.
