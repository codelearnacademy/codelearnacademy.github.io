# Proyecto, producto y servicio

## Qué vas a conseguir

Diferenciar proyecto, producto y servicio dentro de una organización tecnológica.

## Punto de partida

El centro financia un piloto de CodeTasks durante seis semanas, pero espera utilizar el resultado durante varios cursos.

## Conceptos clave

- **Proyecto:** esfuerzo temporal con objetivos y límites.
- **Producto:** solución que evoluciona durante su vida útil.
- **Servicio:** prestación continuada que permite obtener un resultado.

## Desarrollo

El proyecto organiza una intervención acotada: construir el piloto o migrar datos. El producto puede existir antes y después de ese proyecto. El servicio incluye operar la aplicación y atender necesidades de sus usuarios, si se ofrece de esa forma.

No son etiquetas incompatibles. Una organización puede ejecutar un proyecto para mejorar un producto que ofrece como servicio. El cierre del proyecto no elimina las necesidades de actualización, soporte o retirada del producto. Deben definirse responsables para esa continuidad.

## Ejemplo guiado

En CodeTasks, «piloto en seis semanas» es el proyecto; la aplicación con sus versiones es el producto; mantenerla accesible y atender incidencias forma parte del servicio. Al cerrar el piloto, el centro decide quién conserva copias, aplica actualizaciones y responde cuando falla el acceso.

## Relación con otras rutas

Docker facilita distribuir el producto; Git conserva su evolución; las prácticas de operación sostienen el servicio.

## Ejercicios propuestos

1. Clasifica «migrar CodeTasks», «CodeTasks versión 2» y «atender incidencias de acceso».
2. Define un criterio para cerrar el proyecto piloto.
3. Enumera tres responsabilidades que continúan después del cierre.

## Qué debes recordar

El proyecto termina; el producto y su operación pueden continuar. Hay que planificar la transferencia de responsabilidades.
