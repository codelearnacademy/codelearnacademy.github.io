# Qué es una metodología de desarrollo

## Qué vas a conseguir

Diferenciar proceso, metodología, práctica, marco de trabajo y herramienta.

## Punto de partida

Un equipo dice que «usa Git como metodología». Para organizarse necesita distinguir herramienta y forma de trabajo.

## Conceptos clave

- **Proceso:** actividades y relaciones para obtener resultados.
- **Metodología:** conjunto organizado de métodos y criterios de trabajo.
- **Marco de trabajo:** estructura que deja decisiones de aplicación abiertas.
- **Práctica y herramienta:** forma concreta de trabajar y medio que la apoya.

## Desarrollo

Las palabras se utilizan a veces con sentidos distintos; conviene explicitar qué significan en el equipo. Un proceso describe, por ejemplo, cómo una petición llega a producción. Una revisión de código es una práctica. Git es una herramienta de control de versiones. Scrum proporciona un marco de trabajo.

Adoptar una herramienta no define quién decide prioridades, cómo se comprueba la calidad o cómo se mejora el proceso. Estas decisiones deben acordarse según el contexto y revisarse con evidencias.

## Ejemplo guiado

En CodeTasks acordamos revisar cambios antes de integrarlos: esa es la práctica. Usamos una solicitud de cambios en el repositorio como soporte. El flujo desde petición hasta entrega es el proceso. Ninguna de estas decisiones obliga por sí sola a trabajar con Sprints.

## Relación con otras rutas

Git y Maven son herramientas; revisión y automatización son prácticas que pueden apoyarse en ellas.

## Ejercicios propuestos

1. Clasifica Git, revisión de código, Scrum y el flujo de atención de incidencias.
2. Describe una práctica que pueda realizarse con distintas herramientas.
3. Identifica una decisión organizativa que instalar un tablero no resuelve.

## Qué debes recordar

Las herramientas apoyan prácticas y procesos. Instalar una aplicación no equivale a adoptar una forma de trabajo completa.
